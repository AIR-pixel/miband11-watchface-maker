# 手环 11 动态表盘制作工具（Windows 版）

把**视频 / GIF / 静态图**一键做成可安装到小米手环 11（212×520）的动态表盘 `.face`。

> 本文件只讲 Windows 版。**仓库总览（含安卓版、配置说明、免责声明）见 [仓库根 README](../README.md)**。
> `.face` 二进制格式见 [`docs/face格式规范.md`](../docs/face格式规范.md)。

差异化点（相对现成的表盘工具）：

- **框选裁剪区域** —— 拖拽选择要保留的画面（比例自动锁定 212:520，无黑边），支持滚轮缩放
- **截取区间 + 帧数上限** —— 体积的第一杠杆是帧数，不是色深（见下方「体积怎么控制」）
- **压缩程度可选** —— RGB / P256 / P128 / P64 / P32 / P16 六档
- **编码格式可选** —— PNG（无损调色板）或 JPEG（有损，q90/q85/q80/q70/q60 五档质量，已真机验证可用）
- **帧率可选** —— 6 / 8 / 12 / 16 / 20 / 24 / 30 FPS，或沿用源素材帧率
- **帧数触顶时二选一** —— 默认「保时长、降帧率」；勾「保持帧率、压缩时长（快放）」则保帧率、播放变快
- **实时体积预估** —— 改参数立刻显示「预计 N 帧 · 约 X MB · 播放 X s」，超出预算标红

> 纯命令行也能跑，便于脚本化。

## 体积怎么控制（实测数据）

单帧 212×520 编码后体积实测：

| 档位 | 每帧 | 档位 | 每帧 |
|---|---|---|---|
| RGB 真彩 | 146.8 KB | P32 | 31.6 KB |
| P256 | 66.7 KB | P16 | **20.4 KB** |
| P128 | 53.0 KB | P8 | 14.3 KB |
| P64 | 41.5 KB | JPEG q90 | 41.4 KB |
| JPEG q85 | 32.7 KB | JPEG q80 | **27.5 KB** |
| JPEG q70 | 21.4 KB | JPEG q60 | 17.7 KB |

两条结论：

1. **色深是次要杠杆**：P256 → P64 每帧只降 38%；而帧率 24 → 8 FPS 让帧数直接降 67%、体积同比例下降。
   一段 8 秒素材在 24 FPS 下有 192 帧，即使 P64 也有 7.8 MB —— 这时应该先砍时长/帧率，而不是继续压色深。
2. **`.face` 里还有 431 KB 的固定开销**（尾部位图 212×520 RGBA8888，用于表盘选择器预览）。
   帧数很少时它可能比全部帧数据还大，所以别指望把几十 KB 的小表盘再压下去。

想进一步缩小，按这个顺序调：**截取时长 → 帧率 → 帧数上限 → 色深档位 → 编码格式（JPEG）**。

### PNG 还是 JPEG

两者不是单纯替代，体积相同也不代表观感相同：

| | 优点 | 缺点 |
|---|---|---|
| **P64 PNG** | 无损、平涂区干净、无噪点 | 只有 64 色，渐变/肤色处有**色带** |
| **JPEG q80** | 连续色调无色带、体积只有 P64 的 **0.66 倍** | 有损，边缘有**蚊子噪点/块效应** |

经验：**真人 / 照片 / 渐变多的素材用 JPEG q80**，**动漫平涂 / 色块清楚的用 PNG P64**。

JPEG 的甜点区在 **q80~q85**：q90 以上体积反超 P64 PNG，而 P64 是无损的，还不如直接用 PNG。

> 另外，JPEG 在 PC 端会**关掉色度子采样（4:4:4）** —— PIL 默认的 4:2:0 会把色度砍到 106×260，
> 彩色边缘明显串色。实测关掉它只多 19% 体积，色度 PSNR 却涨 2.5 dB，是性价比最高的一刀。
> **安卓端做不到**：`Bitmap.compress` 固定 4:2:0，所以安卓导出的 JPEG 质量天花板低于 PC 端。

### 帧数触顶时：流畅度 × 时长 只能保一个

上面那条 8 秒 / 192 帧的素材，假设你把帧数上限压到 46 帧，就必须放弃一样：

| 模式 | 抽帧 | 播放 | 结果 |
|---|---|---|---|
| **默认**（保时长、降帧率） | 46 帧摊满 8 秒 = 5.75 FPS | 5.75 FPS × 8.0 s | 内容完整、时长不变，**明显掉帧** |
| **快放**（保帧率、压时长） | 46 帧摊满 8 秒 = 5.75 FPS | 24 FPS × 1.9 s | **流畅**、内容完整，但播放变成 **4.17 倍速** |

两者抽的是同一批帧、体积完全一样，区别只在 `main.lua` 里的 `period`（83 ms vs 42 ms）。
所以「最小体积 + 流畅」是能同时拿到的，代价是时长被压掉。素材本来就短于帧数上限时不会触发快放。

## 环境准备

```bash
pip install -r requirements.txt   # Pillow + PyQt5
```

- **处理视频**需要 `ffmpeg`（GIF / 图片不需要）。装好后加入 PATH。
- **打包 .face** 需要 `Compiler.exe`。见下方「Compiler.exe 自备说明」。

## 使用

### GUI

```bash
python main.py
```

1. 拖入或选择视频 / GIF / 图片
2. 在左侧画面框选裁剪区域（拖动框移动，拖右下角蓝点缩放，或直接滚轮缩放）
3. 选截取区间、帧率、帧数上限、压缩等级、编码格式（选 JPEG 后下面的「JPEG 质量」才可用），以及是否叠加时间日期、表盘名称与 ID
4. 帧数触顶时决定要不要勾「保持帧率、压缩时长（快放）」
5. 看「预估」行确认体积与播放时长（超出预算会标红）
6. 点「生成 .face」

产物默认输出到素材同目录的 `watchface_out/` 下。

### 命令行

```bash
python main.py --cli \
  --src 素材.gif --level balanced --fps 12 --max-frames 96 \
  --clip-start 0 --clip-dur 4 \
  --name MyFace --compiler "path/to/Compiler.exe"
```

常用参数：`--level high|balanced|small|tiny|micro|nano`、`--fps 12`、`--clip-start 2.0`、
`--clip-dur 4.0`（省略取到结尾）、`--max-frames 96`、`--fmt png|jpg`、`--jpg-quality 80`、
`--speedup`（快放）、`--crop x0,y0,x1,y1`、`--id 87260401`、`--no-time`、`--out 输出目录`。

## 安装到手表

生成的 `.face` 用 **表盘自定义工具**（配合 Mi Fitness 修改版）或 Mi Fitness 官方
表盘通道安装到小米手环 11。本工具只负责生成 `.face`，不涉及安装链路。

## Compiler.exe 自备说明

`Compiler.exe` 来自 [m0tral/EasyFace](https://github.com/m0tral/EasyFace)，该仓库**没有开源协议**
（`license = null`），默认保留所有权利，且本质是从小米官方 Vela IDE 提取的编译器。

因此本项目**不打包、不分发** `Compiler.exe`：

- 首次使用在界面「3. Compiler.exe」处指定它的路径（会记住，存到 `~/.watchface_tool.json`）；
- 或把它放到本工具目录下（`assets/Compiler.exe` 或项目根 `Compiler.exe`）自动识别。

详细合规说明见 [仓库根的 NOTICE](../NOTICE)。

## 已知限制

- **24 FPS 是流畅度边界**：实测 33 FPS 卡顿、24 FPS 正常、16 FPS 更稳。帧率越高 `.face` 越大。
  默认给 12 FPS + 96 帧上限，是为了避免 8 秒素材一上来就产出 7 MB 以上的表盘。
- **体积预算**：手环表盘建议 ≤ 3.5 MB。超了就按「截取时长 → 帧率 → 帧数上限 → 色深」的顺序调。
- **PNG 和 JPEG 都已真机验证可用**（2026-09-29 确认。此前 JPEG 曾被标为「实验项」，因为不确
  定 miwear 是否编入了 JPG 解码器 —— 实测能正常显示，只要 lua 引用的扩展名与实际文件名一致）。
  早期样本 `vela/test-faces/JPEGTest.face` 即为 JPEG 路线验证件。
- 视频需要 ffmpeg；GIF 直接走 Pillow，无需 ffmpeg。
- 暂未做主体/人脸自动跟踪，框选后各帧用同一裁剪窗（后续可加）。
